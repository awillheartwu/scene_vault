# Scene Vault 项目背景

## 产品定位

Scene Vault 是面向各类游戏截图管理和创作资料整理的 Windows 本地优先桌面工具。
它结合素材索引、项目资料、Capture Session 和可选 AI 辅助，但不是云端网盘，也不以
多人协作为核心。截图来源可以是游戏内置功能、平台工具或其他截图软件，不绑定特定
游戏类型、游戏引擎或截图方式。

产品原则：

- 用户文件默认保留在原位置，数据库保存索引和业务关系。
- 核心素材管理和截图工作流不依赖网络或 Python AI 引擎。
- AI 只提供可替换的增强能力；角色识别必须是建议，人工决定最终结果。
- 文件归档必须可恢复，NAS 断线或应用重启不能导致成果丢失。

## 当前能力

- Tauri 2 + Vue 3 桌面应用，Rust Services 负责业务规则，SQLite 保存状态。
- 项目、角色、截图会话、Capture Item、素材关系和设置数据。
- 多来源截图目录、会话基线、增量发现、已有截图导入和内容去重。
- 人物 / 游戏截图 / 收藏三分类，以及组合或拆分的快捷键工作台。
- 人物图视觉处理、可配置归档命名、NAS 可靠归档和失败恢复。
- 项目人物工作台：浏览、改判、重新处理、识别建议复查和 Face Bank 管理。
- 项目一对一 Markdown 快速笔记，写入项目归档目标，支持离线暂存、恢复同步和冲突备份。
- 可选 SFace / ArcFace 识别器；模型身份隔离，切换后可重建样本库。

通用素材扫描、标签、合集以及 OCR、描述、Embedding、语义搜索和 RAG 尚未完成，
以[路线图](ROADMAP.md)为准。

## Capture Session

Scene Vault 的端到端截图工作流适用于各类游戏：

1. 用户为项目配置一个或多个截图来源目录和归档目标目录。
2. 用户继续使用游戏内置、平台或第三方截图工具。
3. Rust 发现稳定写入的新图片并建立待分类记录。
4. 用户选择人物、游戏截图或收藏；人物图再选择一个主角色。
5. 可选 Python 引擎处理单张人物图，返回人脸、标注图、头像和识别特征。
6. Rust 校验结果并可靠归档到本地目录或 NAS。
7. SQLite 保存会话、处理状态、人工决定、建议和错误历史。

数据模型和处理协议不写死为特定游戏、游戏引擎或截图工具。完整流程见
[Capture Session 工作流](CAPTURE_WORKFLOW.md)。

## 已确认的产品决策

- 三分类、四目录、组合/拆分快捷键窗口和项目笔记的长期语义见
  [截图分类与快速笔记决策](decisions/2026-08-05-capture-classification-and-notes.md)。
- 一张人物截图当前只有一个主角色；多人脸数据层已预留，但多人逐脸 UI 暂不开发。
- 归档命名可配置，只影响新归档；`{character}` 始终表示主角色。
- 人工确认优先于 Face Bank 建议；无脸、低质量或模型身份不完整的结果不能污染样本库。
- ArcFace 权重由用户自备，不随项目分发；模型效果与阈值以
  [BENCHMARK.md](BENCHMARK.md) 为唯一评测依据。

## 当前阶段

Capture Session 与 Face Bank 的主要代码路径已完成，下一步首先进行 Windows 原生
端到端验收。人物工作台仍需接入角色合并和代表头像 UI；随后再回到通用素材索引、
Sidecar 交付和其他路线图事项。

## 非目标

- 当前阶段不实现云同步或多人协作。
- 不把素材二进制写入 SQLite。
- 不让 Python 扫描游戏目录、修改主数据库或直接写 NAS。
- 不默认向游戏注入按键。
- 不在真实需求出现前开发多人逐脸标注 UI。
