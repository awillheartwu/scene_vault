# 截图分类与快速笔记决策

状态：已确认并已实施。本文保留长期产品语义；当前工作流和验收方法分别见
[Capture Session 工作流](../CAPTURE_WORKFLOW.md) 与 [开发指南](../DEVELOPMENT.md)。

## 背景与目标

Scene Vault 从用户配置的截图目录发现新图片后，需要让用户用很少的操作完成分类、
人物标记和快速笔记。截图可以来自游戏内置、平台或第三方工具；核心流程必须离线可用，
不能依赖 Python AI，也不能移动或删除原始截图。

## 截图分类

新截图先进入待分类状态，必须选择以下一种分类：

| 值 | 产品语义 | 处理方式 |
|---|---|---|
| `person` | 人物截图 | 选择主角色；视觉引擎可用时生成标注图和头像 |
| `scene` | 游戏场景或鉴赏截图 | 跳过 AI，原图归档 |
| `private` | 收藏或私藏截图 | 跳过 AI，原图归档，默认隐藏 |

未分类截图不处理、不归档，可随时在应用内补分类。人工选择始终是最终依据；Face Bank
等 AI 能力只能给出建议，低置信度或多脸结果必须允许用户确认、拒绝或改判。

## 触发与弹窗

- 提供全局快捷键和应用内工作台两个入口。
- 分类和笔记各有一个可配置快捷键，默认分别为 `Ctrl+Shift+S` 和
  `Ctrl+Shift+N`。
- 默认使用组合工作台：分类与笔记并排显示，任一侧可折叠，但至少保留一侧。
- 用户可切换为拆分模式，让两个快捷键分别呼出分类窗口和笔记窗口。
- 弹窗记住最近使用的项目和会话；新截图出现时刷新待分类队列。
- 完成一张后自动切换下一张。最后一张完成后保留空状态；仅在用户启用“无待分类时
  自动关闭”后才延时隐藏。
- 人物分类应复用最近角色并允许新建角色；场景和收藏分类不要求额外输入。

## 归档目录

每个项目配置一个归档目标目录。其下固定使用四个中文目录：

```text
<destination_directory>/
├── 人物图/
├── 头像图/
├── 游戏截图/
└── 收藏图/
```

人物截图的标注大图和头像分别进入前两个目录；场景和收藏截图保存原图。所有归档继续
使用“本地生成 → 复制临时文件 → 校验 → 原子重命名”，源文件永不删除。归档文件名
遵循用户配置的命名模板，只影响新归档。

## 收藏图隐私

收藏图在历史、统计和搜索中默认隐藏，用户可以显式切换显示。当前是单机单用户产品，
不提供密码或加密层。

## 项目快速笔记

- 一个项目对应一份 Markdown 笔记，文件名为 `笔记.md`。
- 文件位于项目归档目标目录根部，便于与归档一起管理，并可由
  Obsidian 等外部编辑器打开。
- 内容先保存到 SQLite，再由后台任务写入目标目录；NAS 断线时继续本地暂存，恢复后
  自动同步。
- 写入采用临时文件、读回校验和原子替换。检测到外部修改时，先保留带时间戳的冲突
  备份，再写入本地版本。
- 编辑区支持 Markdown 预览；用户可配置失焦自动保存。

## 故障与冲突原则

- NAS 不可用时，截图归档和笔记同步都保留可恢复状态，不丢弃本地成果。
- 应用重启后继续恢复队列和同步状态。
- 冲突优先保留两份内容，不静默覆盖唯一副本。
- AI 不可用时，人物截图仍可人工标记并降级归档；之后可重新识别补齐派生产物。

## 非目标

- 不向游戏进程注入按键，也不依赖特定游戏、引擎或截图工具。
- 不改用系统文件事件；当前截图发现继续使用目录轮询和稳定性校验。
- 不实现云同步、多人协作、收藏图密码或加密。
- 不实现多人逐脸标注 UI；当前一张人物截图只有一个主角色。
- 长评编写功能仅保留为未来事项，等待用户提供“长评维度”。

## Windows 验收标准

- 两个快捷键在组合和拆分模式下都能唤起正确窗口，设置修改即时生效。
- 新截图能进入待分类队列，并可从弹窗或工作台完成三分类。
- 四类输出写入正确目录，源截图保持不变；收藏图默认隐藏且可显示。
- 人物图在 AI 可用和不可用两种情况下都能完成流程，后者可在配置 AI 后重新识别。
- `笔记.md` 可保存、预览和被外部编辑；NAS 断线后可暂存，恢复后可同步，冲突会产生
  备份。
- 应用重启后待处理队列、归档重试和笔记同步状态能够恢复。
