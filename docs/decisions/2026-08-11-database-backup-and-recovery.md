# 数据库备份与恢复决策

日期：2026-08-11

## 背景

Scene Vault 的截图源文件和 NAS 归档由用户保管，但项目、角色、分类、处理状态、笔记、
Face Bank 与设置都以 SQLite 为唯一主数据。数据库使用 WAL；运行中只复制
`scene-vault.db` 可能遗漏尚未 checkpoint 的提交，因此不能作为产品备份方式。

## 决策

- 产品备份使用 SQLite `VACUUM INTO` 生成一致的单文件快照，不直接热复制主库、WAL
  或 SHM。
- 每份备份附带 JSON manifest，记录应用版本、Schema 版本、SQLite 版本、UTC 时间、
  文件大小、SHA-256 和关键表行数。
- 备份只包含索引和元数据，不包含源截图、NAS 归档、模型、字体、缩略图或日志。UI 必须
  明确说明这一边界。
- 恢复分成两个阶段：应用运行时只校验并暂存备份；下一次启动在数据库连接池打开前完成
  替换。
- 暂存和启动替换前都要验证 SQLite 文件头、manifest、SHA-256、`quick_check`、
  `foreign_key_check` 和 Schema 兼容性。
- 替换前保留当前主库及其 WAL/SHM 的 pre-restore 副本。替换后校验或迁移失败时回滚，
  不把失败恢复留作下一次正常启动的主库。
- 启动无法打开主库时仍启动最小恢复界面，只提供选择备份、打开数据目录、复制错误摘要和
  重启，不启动截图监听、笔记同步或 AI worker。
- 检测到待执行迁移时，在迁移前自动生成一致性备份，默认保留最近三份。
- `REINDEX` 与 `ANALYZE` 作为显式“数据体检与维护”操作；1.0 不提供在线 `VACUUM`
  压缩入口。

## 安全不变量

1. 连接池打开期间不得替换、重命名或删除主数据库文件。
2. 恢复来源不能是当前主库、WAL、SHM 或已经暂存的恢复文件。
3. 不接受来自更高 Schema 版本的备份；旧 Schema 备份恢复后只通过内嵌追加迁移升级。
4. 已执行的 SQLx 迁移不修改，恢复和升级都必须通过 checksum 校验。
5. 备份、恢复、回滚和维护结果写入 `data.maintenance` 结构化日志，但日志不得记录完整
   用户路径。
6. 自动备份清理只能删除应用自己创建且 manifest 可识别的文件。

## 产品入口

正常模式在“设置 → 资源与存储”中提供：数据体检、立即备份、从备份恢复、打开备份目录
和重建索引。恢复操作必须二次确认并说明应用会重启。

恢复模式不依赖主数据库连接池。恢复成功后重启进入正常模式；恢复失败时保留原始文件和
诊断信息，允许重新选择备份。

## 验收

- 在 WAL 有未 checkpoint 提交时创建备份，独立打开后数据完整。
- 拒绝篡改 manifest、篡改数据库、非 SQLite 文件、外键损坏和更高 Schema 版本。
- 暂存恢复不会改变运行中的主库。
- 启动替换失败和迁移失败都能恢复 pre-restore 数据。
- 主库损坏时应用仍能显示恢复模式并从有效备份恢复。
- 升级前自动备份数量受限，且不会删除用户手工选择的备份。
