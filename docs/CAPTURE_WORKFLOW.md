# Capture Session 工作流

## 目标

用户可以继续使用游戏内置、平台或第三方截图工具。Scene Vault 监听用户配置的截图
目录，在后台发现新图片，提供快速分类和人物标记，可选生成标注图、头像与角色建议，
并把结果可靠归档到本地目录或 NAS。原始截图始终保留。

## 会话准备与发现

1. 项目保存一个或多个截图来源目录以及默认归档目标。
2. 开始会话时，Rust 为所有启用来源建立已有文件基线。基线快照漏掉的历史文件（例如
   旧版本创建的会话）在发现时按修改时间判定为回填，与显式导入一样等待手动开始识别。
3. 后台每 2 秒扫描图片，等待写入稳定后登记；同名文件内容变化仍视为新截图。
4. 多来源中的相同内容只导入一次。用户也可显式导入来源目录中未登记的已有截图；导入
   只登记记录，不生成整批缩略图，也不自动开始识别。

截图发现和核心分类不依赖 Python。正式配置使用 Windows 或 UNC 路径，不保存 WSL
路径。

## 分类与处理

新截图进入 `awaiting_label`：

- `person`：选择一个主角色并入队。视觉引擎可用时检测人脸、标注姓名、裁剪头像并
  提取可选特征；无人脸是成功降级，保留标注大图但没有头像。
- `scene`：跳过 Python，原图进入“游戏截图”。
- `private`：跳过 Python，原图进入“收藏图”，并在历史、统计和搜索默认隐藏。
- `unclassified`：保持待分类，不处理、不归档。

显式导入和早于会话开始回填的 `awaiting_label` 记录带有持久化识别闸门。用户点击“开始
识别导入截图”后，Rust worker 才按最旧优先、一次一张提取特征；会话进行中新生成的截图
属于实时捕获，不经过闸门。导入命令会为每张新登记截图广播 `capture:item-created`，捕获
页立即显示，不依赖整页重载。视觉引擎未配置时“开始识别导入截图”不可用并解释原因，图片
处理状态区也会提示 AI 未配置；一旦在设置中配置好引擎，已解除闸门的截图会在空闲时自动
逐张识别。缩略图只在卡片进入可视区域后请求，后端固定串行生成，因此滚动大量导入图片也
不会同时解码整批原图。最近捕获条带展示全部待处理卡片（单次最多取 100 条），完成的截图
进入历史页。

分类和笔记可使用默认组合工作台，也可在设置中拆分成两个独立窗口。快捷键和完整产品
语义见[截图分类与快速笔记决策](decisions/2026-08-05-capture-classification-and-notes.md)。
快捷分类队列始终跟随当前活动监听项目，只展示该项目的待分类截图；没有活动会话时不从
其他项目补取旧队列。

## AI 降级与建议

未配置或无法启动 Python 时，人物图原图归档到“人物图（未识别）”，保留角色和 warning；
配置引擎后可重新识别，并在新归档成功后替换旧的降级归档。

Face Bank 只对相同项目和相同模型身份的主脸特征生成角色建议。建议需要人工确认；多脸
截图明确提示“建议基于主脸”。无脸、低质量、小面积脸或缺模型身份的结果不能留下旧的
污染样本。

建议在特征提取时预计算一次；用户选择“人物”分类时，应用会用当时最新的样本库重新比对
并刷新建议，因此同一批内先完成分类的人物会立刻成为后分类者的比对样本。样本库为空时
跳过比对（第一批导入不会产生建议）。比对是逐样本计算 512 维余弦、按角色取最高分后再
按“绝对分数 + 领先幅度”门槛筛选，耗时随样本数线性增长，单机项目规模下为毫秒级。

## 手动框选主脸

人物分类模式提供「框选主脸」，捕获页和分类弹框共用同一个选框组件。选区保存为相对原图
的归一化坐标，与检测框、可再生的特征分开存放，重建特征或重新识别都不会清掉人工选区；
不设置选区时完全保留原有的自动主脸行为。框选工具直接叠加在当前预览图上，不额外打开
第二张图片；缩放留白不计入选区，支持方向键微调、Shift 调整大小和 Esc 取消。

两端的交互逻辑完全共享（同一组件、同一状态管理、同一后端与引擎流程）；差异只在容器
布局：捕获页预览本来就大，弹窗在框选时会把图片放大到接近整窗并收起角色列表，结束框选
后恢复。新增入口时只需挂载同一组件并传入当前图片与已检测到的主脸框。

- 确认选区后，Rust 用该选区重新检测人脸并重算特征，然后刷新角色推荐。用户已经选好的
  角色不会被覆盖，新推荐只作为提示，由用户决定是否更换。
- 检测优先取整图结果中脸框中心落在选区内的人脸；没有候选时按「扩边重试比例」（默认 0.15，
  可在设置中调，0 表示关闭）把选区向外扩大后重新检测，并把坐标映射回原图，最终候选脸中心
  仍必须落在原选区。候选多于一张时按「选区内多张脸」策略处理：默认报错并要求缩小范围，
  也可以配置为自动选最大或最清晰的一张；始终无脸提示重框，也可以放弃框选回到自动选脸。
- 打开框选时默认框取自这张图最近一次检测到的主脸（没有检测框时才回落到居中区域），
  所以通常只需要微调。框选提示固定在左上角常显且不拦截拖动，失败信息单独显示在下方。
- 失败信息以中文说明原因和处理方式（选区内没人脸、多张脸、原图缺失、模型缺失、AI 未配置
  等），不向用户显示协议里的英文错误码；详细错误码保留在调试日志中。
- 识别期间允许换图，但同一张图片的选区提交串行执行，旧图迟到的结果不会写到当前图片上；
  提交人物分类需要等待本次识别结束或明确放弃框选。
- 推荐、最终标注、头像和确认后写入 Face Bank 的样本使用同一个人工主脸。失败的选区不产生
  可学习样本，也不会把失效的旧推荐显示成新结果。

## 撤销分类

撤销分类把图片退回“待分类”，支持单张、按角色多选，以及撤销当前筛选条件下的全部结果
（含跨页）。历史页和工作台提供入口，撤销后的图片会重新出现在捕获页，不需要重新启动原会话。

- 捕获页仅保留实时处理；历史页的「管理」位于分页行左侧，选择「撤销图片」后进入选择模式。
  点击图片行切换勾选；「全选筛选结果」涵盖跨页图片，翻页保留勾选。「结束多选」未选时直接
  退出，已选时打开确认；未执行便关闭确认则保留勾选，方便继续调整。
- 工作台单图右键可撤销分类，角色右键直接进入多选人物模式并勾选该角色；右上角省略号提供
  图片选择与多选人物撤销入口。多选人物后固定这些角色的截图名单，再使用同一个确认对话框。
- 执行前固定名单，展示数量、不可处理原因和归档清理范围；执行期间不再追加新记录。
- 默认勾选清理旧归档图片和头像，可以取消。取消时明确提示旧归档保留、重新分类可能产生
  另一份文件；保留的文件不会被静默覆盖。
- 原图缺失、被替换或无法读取的图片不执行撤销；排队中、处理中或等待归档的图片同样列为
  不可处理。其余图片正常执行，结束后给出成功、失败和未处理清单。
- 撤销保留原始记录、来源身份、捕获时间和会话归属，清除分类、角色关联、建议、人工选区、
  检测特征、该图片贡献的 Face Bank 样本、处理错误和派生产物引用；不加入内容忽略表、
  不删除角色，也不影响其他图片或项目共享素材。
- 清理沿用既有规则：本地目标移入 Windows 回收站，NAS/UNC 在二次确认后永久删除，原图
  永不删除；文件清理失败的图片不会报告撤销成功。任务只在内存里推进、不落库，进度以
  「调试日志」（capture.reset）为准：批次运行中关闭窗口不会中断它，应用被强杀则下次启动
  释放占用、图片保持原分类，重新发起就能继续；数据库回滚不代表已删除文件可以恢复。
- 共享引用检查在整次执行内缓存规范路径：每个引用路径最多解析一次文件系统并跨图片复用，
  候选文件只解析一次，避免按文件重复扫描全库路径（NAS/UNC 目标上尤其明显）。引用行本身
  仍按图片重新读取，插入新记录后不会漏检；无法解析的引用按失败处理，不会当作无冲突。
  已知边界：缓存只覆盖这一次执行，且会记住"当时不存在"的结果；若执行期间外部把某条引用
  路径变成指向目标的硬链接或符号链接，需要重新发起撤销才会重新判定。
- 确认对话框按状态收尾：全部处理完成后显示绿色「任务完成」（全部因不可处理被跳过时显示
  「任务已结束」），点击即关闭；有失败项时不再显示完成状态，而是给出失败数量、按类别
  说明的原因和处理建议（NAS/网络不可达、文件被占用、没有权限、目标被改动、图片正被其他
  操作占用等），并提供「重试失败项（N）」。未完成的图片排在清单最前。
- 撤销任务不落库、不排队：一次任务只存在于当前会话，失败即结束，图片保持原分类、原图
  不动；重新发起一次撤销即可重试，已清理或已消失的文件按“已完成”跳过。失败原因、耗时和
  每张图片的结果记录在「调试日志」（capture.reset 模块）里，那是它唯一的痕迹。
- 关闭未确认的预览会立刻释放内存中的任务，包括"预览还在读取、结果迟到"的情况。没被正常
  关闭的预览不会自己到期释放，而是在下一次创建任务时被清理：超过两小时仍未被执行的预览
  会在那一次淘汰；任务注册表上限 16 条，超限时先淘汰最久未活动的任务，正在执行的任务
  永远不会被淘汰。已开始的撤销不会因为关闭弹窗而中断。
- 重置成功后图片回到待分类并开启后台串行识别，只生成建议、不自动分类；普通导入原有的
  暂停识别行为不变。AI 不可用时仍可手动分类。

关闭未执行的预览不会有任何残留；选择全部图片只读取候选 ID，不创建任务。应用被强杀时
留在图片上的撤销占用会在下次启动时释放，被中断的图片保持原分类、可再次改判或撤销。

## 可靠归档

目标目录固定包含：人物图、头像图、游戏截图、收藏图。人物图的文件名可按模板配置；
修改模板不重命名已有归档。

每个输出执行“本地生成 → 复制临时文件 → 校验 → 原子重命名”。NAS 断线或复制失败时，
本地结果和状态保留，任务按退避重试并可人工重试。应用重启恢复待归档任务；处理中断会
记录失败而不是无限自动循环。

已完成截图被改判角色或分类时重新处理。旧归档只在新归档成功后移入 Windows 回收站；进行中或待归档项
不能同时改判。

## 文件检查与删除

原图是用户资产，应用永不删除。处理、重新识别、重试或重新归档前，先验证源文件内容身份；
若路径中的文件已被替换，不继续使用旧 Capture Item 写入结果。

已归档历史的原图从外部消失时保留记录并标记为 `missing`；尚未归档且从未形成可用结果的项
仍沿用原有的状态保护清理规则。这里删除的只是数据库项，应用不会删除原图文件。

后台发现已知文件时，先按文件大小和修改时间走快速路径。人物工作台的“检查项目文件”不要求
活动会话，会强制重算整个项目的已知原图哈希，并核对归档目标和头像目标是否仍可用。旧路径
缺失时，只在启用来源目录中按“文件名 + 内容哈希”唯一匹配后重新定位；多个候选不猜测，来源
目录不可访问时不批量误标缺失。检查不会导入无关图片或启动识别。源文件和目标文件分别记录
`available`、`missing`、`replaced`、`unavailable` 状态。

同一路径写入新内容时，新的哈希生成新的 Capture Item，旧历史记录标记为 `replaced`。删除
Capture Item 或人物时，删除归档目标是可选项，默认勾选；原图不受影响。本地目标文件只移动到
Windows 回收站，不提供永久删除回退；UNC/NAS 目标在明确的第二次确认后永久删除。目标已不存在视为完成；目标删除部分
失败时保留全部数据库记录，用户可以重试，已完成或已不存在的目标不会重复处理。

记录成功删除后，本地标注图、头像图和缩略图随记录永久清理，不进入回收站。删除的内容哈希
会加入项目级忽略表：同一项目之后再次出现相同哈希仍保持忽略；内容发生变化则按新哈希重新
进入发现流程。

## 项目笔记

每个项目有一份 `笔记.md`，同步到项目归档目标目录根。内容先写 SQLite；NAS 离线时
本地暂存并持续重试。检测到外部修改时，先保留时间戳备份，再原子写入当前版本。

## 显式标注人物开关

设置 → 通用设置 →「显式标注人物」（默认开启）。这个开关只决定「是否把角色名字画到
截图副本上」，识别本身不受任何影响。

- **开启（默认）**：识别后生成标注图（名字+人脸框），归档时存到 `归档目录/人物图/`；
  工作台/历史提供「标注」预览变体。
- **关闭**：跳过标注图生成，其余全部照常——检测、识别、脸向量入库、Face Bank 建议、
  头像图、角色命名归档；归档时原图按角色命名存到 `归档目录/人物图（原图）/`。
  仅影响之后新处理的截图，已有数据不变。
- **降级与重新识别**：与开关无关。completed 人物图在「无标注输出 且 无检测输出」时
  视为降级（引擎未配置或失败），显示「未识别 N」并提供「重新识别」入口；已识别但
  未标注的截图不视为降级。「重新提取人脸特征」对单张图始终可用。

## Windows 原生端到端验收

### 基础环境

- [x] `pnpm test` 和 `pnpm build` 在 Windows 通过。
- [x] Tauri 应用能启动，主窗口和快捷键弹窗正常显示。
- [x] AI 未配置时应用可启动并完成非 AI 流程；配置后健康检查为 ready。

### 截图发现与分类

- [x] 多个启用来源都能发现真实游戏截图；会话开始前旧图不会误导入。
- [x] 覆盖同名截图可再次发现；不同来源的相同内容只导入一次。
- [x] “导入已有截图”只登记未入库图片；点击显式按钮前不识别、不批量生成缩略图，点击
  后识别与缩略图解码均严格一次一张。
- [x] 人物、游戏截图、收藏和待分类状态符合语义；收藏默认隐藏且可显示。
- [x] 组合与拆分窗口、两个全局快捷键、失焦保存和空队列自动关闭设置正确。
- [x] 快捷分类弹窗只显示当前活动监听项目的待分类截图，不混入其他项目队列。

### 人物处理与 Face Bank

- [x] 真实截图能生成标注图、头像和 Face Bank 样本。
- [x] 点击“确认建议”会实际改变主角色、重新处理并生成新 NAS 归档；旧归档、旧头像和
  旧资产关系被替换。
- [x] 拒绝建议和人工改判不会残留错误状态。
- [x] 无脸、低质量、小面积脸和缺模型身份不会保留旧样本；暂时性引擎失败会明确报告
  保留状态。
- [x] SFace / ArcFace 切换后兼容状态正确，跨模型不比较，一键重建结果和失败分类准确。
- [x] 角色重命名、合并和代表头像操作通过约束与归档行为验收。

### 故障恢复

- [x] NAS 断线时截图归档和笔记同步保留本地结果；恢复后自动或手动重试成功。
- [x] 外部修改 `笔记.md` 后再次保存会生成冲突备份。
- [x] 应用在处理、待归档和笔记待同步状态下重启，队列与状态恢复正确。
- [x] 源截图在成功、失败、改判和重试过程中都未被移动或删除。

### 框选主脸与撤销分类

- [ ] 框选另一张脸后推荐按新特征刷新；人工选择的角色保持，最终头像和标注对应同一主脸。
- [ ] 无脸、多脸、小脸、选区越界、缩放留白、快速换图、连续框选和旧结果迟到都有明确提示，
  失败选区不产生可学习样本。
- [x] 单张、角色多选、跨页全部、已结束会话、原图缺失或替换、共享引用及取消归档清理的
  撤销行为符合预期（用户验收，见下方 2026-09-14 记录）。

## 不迁入 Python 的职责

Python 不保存目录配置、不扫描来源、不按 `names.txt` 批处理、不维护任务队列、不修改
SQLite，也不直接写 NAS。这些职责始终由 Rust Services 和 Vue 交互承担。
