# Capture Session 工作流

## 目标

用户可以继续使用游戏内置、平台或第三方截图工具。Scene Vault 监听用户配置的截图
目录，在后台发现新图片，提供快速分类和人物标记，可选生成标注图、头像与角色建议，
并把结果可靠归档到本地目录或 NAS。原始截图始终保留。

## 会话准备与发现

1. 项目保存一个或多个截图来源目录以及默认归档目标。
2. 开始会话时，Rust 为所有启用来源建立已有文件基线。基线快照漏掉的历史文件（例如
   旧版本创建的会话）在发现时按修改时间判定为回填，与显式导入一样等待手动开始识别。
3. 后台每 2 秒扫描图片，等待写入稳定后登记；同名文件内容变化仍视为新截图。
4. 多来源中的相同内容只导入一次。用户也可显式导入来源目录中未登记的已有截图；导入
   只登记记录，不生成整批缩略图，也不自动开始识别。

截图发现和核心分类不依赖 Python。正式配置使用 Windows 或 UNC 路径，不保存 WSL
路径。

## 分类与处理

新截图进入 `awaiting_label`：

- `person`：选择一个主角色并入队。视觉引擎可用时检测人脸、标注姓名、裁剪头像并
  提取可选特征；无人脸是成功降级，保留标注大图但没有头像。
- `scene`：跳过 Python，原图进入“游戏截图”。
- `private`：跳过 Python，原图进入“收藏图”，并在历史、统计和搜索默认隐藏。
- `unclassified`：保持待分类，不处理、不归档。

显式导入和早于会话开始回填的 `awaiting_label` 记录带有持久化识别闸门。用户点击“开始
识别导入截图”后，Rust worker 才按最旧优先、一次一张提取特征；会话进行中新生成的截图
属于实时捕获，不经过闸门。缩略图只在卡片进入可视区域后请求，后端固定串行生成，因此
滚动大量导入图片也不会同时解码整批原图。最近捕获条带展示全部待处理卡片（单次最多取
100 条），完成的截图进入历史页。

分类和笔记可使用默认组合工作台，也可在设置中拆分成两个独立窗口。快捷键和完整产品
语义见[截图分类与快速笔记决策](decisions/2026-08-05-capture-classification-and-notes.md)。
快捷分类队列始终跟随当前活动监听项目，只展示该项目的待分类截图；没有活动会话时不从
其他项目补取旧队列。

## AI 降级与建议

未配置或无法启动 Python 时，人物图原图归档到“人物图（未识别）”，保留角色和 warning；
配置引擎后可重新识别，并在新归档成功后替换旧的降级归档。

Face Bank 只对相同项目和相同模型身份的主脸特征生成角色建议。建议需要人工确认；多脸
截图明确提示“建议基于主脸”。无脸、低质量、小面积脸或缺模型身份的结果不能留下旧的
污染样本。

建议在特征提取时预计算一次；用户选择“人物”分类时，应用会用当时最新的样本库重新比对
并刷新建议，因此同一批内先完成分类的人物会立刻成为后分类者的比对样本。样本库为空时
跳过比对（第一批导入不会产生建议）。比对是逐样本计算 512 维余弦、按角色取最高分后再
按“绝对分数 + 领先幅度”门槛筛选，耗时随样本数线性增长，单机项目规模下为毫秒级。

## 可靠归档

目标目录固定包含：人物图、头像图、游戏截图、收藏图。人物图的文件名可按模板配置；
修改模板不重命名已有归档。

每个输出执行“本地生成 → 复制临时文件 → 校验 → 原子重命名”。NAS 断线或复制失败时，
本地结果和状态保留，任务按退避重试并可人工重试。应用重启恢复待归档任务；处理中断会
记录失败而不是无限自动循环。

已完成截图被改判角色或分类时重新处理。旧归档只在新归档成功后删除；进行中或待归档项
不能同时改判。

## 项目笔记

每个项目有一份 `笔记.md`，同步到项目归档目标目录根。内容先写 SQLite；NAS 离线时
本地暂存并持续重试。检测到外部修改时，先保留时间戳备份，再原子写入当前版本。

## Windows 原生端到端验收

### 基础环境

- [ ] `pnpm test` 和 `pnpm build` 在 Windows 通过。
- [ ] Tauri 应用能启动，主窗口和快捷键弹窗正常显示。
- [ ] AI 未配置时应用可启动并完成非 AI 流程；配置后健康检查为 ready。

### 截图发现与分类

- [ ] 多个启用来源都能发现真实游戏截图；会话开始前旧图不会误导入。
- [ ] 覆盖同名截图可再次发现；不同来源的相同内容只导入一次。
- [ ] “导入已有截图”只登记未入库图片；点击显式按钮前不识别、不批量生成缩略图，点击
  后识别与缩略图解码均严格一次一张。
- [ ] 人物、游戏截图、收藏和待分类状态符合语义；收藏默认隐藏且可显示。
- [ ] 组合与拆分窗口、两个全局快捷键、失焦保存和空队列自动关闭设置正确。
- [ ] 快捷分类弹窗只显示当前活动监听项目的待分类截图，不混入其他项目队列。

### 人物处理与 Face Bank

- [ ] 真实截图能生成标注图、头像和 Face Bank 样本。
- [ ] 点击“确认建议”会实际改变主角色、重新处理并生成新 NAS 归档；旧归档、旧头像和
  旧资产关系被替换。
- [ ] 拒绝建议和人工改判不会残留错误状态。
- [ ] 无脸、低质量、小面积脸和缺模型身份不会保留旧样本；暂时性引擎失败会明确报告
  保留状态。
- [ ] SFace / ArcFace 切换后兼容状态正确，跨模型不比较，一键重建结果和失败分类准确。
- [ ] 角色重命名、合并和代表头像操作通过约束与归档行为验收。

### 故障恢复

- [ ] NAS 断线时截图归档和笔记同步保留本地结果；恢复后自动或手动重试成功。
- [ ] 外部修改 `笔记.md` 后再次保存会生成冲突备份。
- [ ] 应用在处理、待归档和笔记待同步状态下重启，队列与状态恢复正确。
- [ ] 源截图在成功、失败、改判和重试过程中都未被移动或删除。

## 不迁入 Python 的职责

Python 不保存目录配置、不扫描来源、不按 `names.txt` 批处理、不维护任务队列、不修改
SQLite，也不直接写 NAS。这些职责始终由 Rust Services 和 Vue 交互承担。
